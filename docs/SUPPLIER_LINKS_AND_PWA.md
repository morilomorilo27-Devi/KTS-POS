# الموردون المتعددون ونسخة PWA

## ربط الأصناف بالموردين

يدعم الصنف صفرًا أو موردًا واحدًا أو عدة موردين من خلال جدول الربط `product_suppliers`. يعرض `GET /api/products` و`GET /api/products/:id` الحقول التالية للمستخدم المخوّل بإدارة الكتالوج:

- `supplier_ids`: معرّفات الموردين المرتبطين.
- `suppliers`: بيانات موجزة تشمل المعرّف والرمز والاسم والحالة.
- `supplier_names`: أسماء جاهزة للعرض في جدول الأصناف.

يقبل `POST /api/products` و`PUT /api/products/:id` الحقل `supplier_ids` كمصفوفة JSON أو كنص JSON في طلب `multipart/form-data`. الحقل اختياري؛ غيابه يحافظ على العلاقات عند التعديل، وإرسال مصفوفة فارغة يزيل العلاقات. تتحقق الخدمة من وجود جميع الموردين وتحفظ الصنف والعلاقات في معاملة واحدة. يستمر تسجيل التوريد في إضافة علاقة المورد بالصنف تلقائيًا.

يحتوي نموذج إضافة وتعديل الصنف على قائمة اختيار متعددة. يمكن إنشاء الصنف دون مورد وربطه لاحقًا من النموذج أو من أول عملية توريد.

## تطبيق الويب التقدمي

يتضمن النظام `manifest.webmanifest` بهوية عربية واتجاه RTL ووضع عرض مستقل، وأيقونات 192 و512 بكسل وأيقونة Maskable وأيقونة Apple Touch. يظهر زر التثبيت في شريط العمليات عندما يدعم المتصفح حدث التثبيت.

يخزن Service Worker الإصدار الرابع غلاف التطبيق وملفات التصميم والسكريبتات والهوية والأيقونات. تستخدم طلبات الواجهة أسلوب الشبكة أولًا مع الرجوع إلى النسخة المحلية، وتعود طلبات التنقل إلى `index.html` عند انقطاع الشبكة. تبقى طلبات API تحت إدارة منطق العمل دون اتصال الموجود في النظام.

على `localhost` أو عبر HTTPS يمكن تثبيت التطبيق من زر التثبيت أو من قائمة المتصفح. بعد الزيارة الأولى واكتمال تسجيل Service Worker يمكن فتح الواجهة دون اتصال واستخدام مسار البيع المحلي المعتمد سابقًا.
