# KTS POS — جمعية المعلمين الكويتية

نظام محلي لإدارة المبيعات والمكتبة والقرطاسية. يستخدم Node.js وExpress وSQLite وواجهة عربية Vanilla HTML/CSS/JS. نُفذ وفق الوثائق الخمس في `SYSTEM_REPLICA_DOCS`، مع اعتماد تصميم Institutional Slate V2، والمحاسبة الداخلية بدل Odoo حسب توجيه المستخدم اللاحق.

## التشغيل

يلزم Node.js 22.19 أو أحدث يدعم `node:sqlite`. افتح PowerShell في مجلد المشروع:

```powershell
npm install
npm start
```

افتح `http://127.0.0.1:5000`. يتوقف الخادم باستخدام Ctrl+C إذا شُغّل في الطرفية. يمكن تشغيل `start.cmd` أيضًا.

| الحساب | كلمة المرور | الدور |
|---|---|---|
| admin | admin123 | مدير النظام |
| cashier1 | cashier123 | كاشير |

تغيير بيانات الحسابات متاح من الإدارة ← المستخدمون. تشفير كلمات المرور مطابق للخوارزمية والـ salt المحددين في الوثائق. لا تُسجل كلمات المرور أو تجزئاتها في سجل التدقيق.

## بدء التشغيل التشغيلي

1. افتح الإدارة، أضف الأصناف والباركودات أو استورد ملف CSV/XLSX. الفئات الخمس وفئات العضوية الأربع وقواعد خصمها موجودة مسبقًا. لا تُزرع منتجات أو أعضاء وهميون في قاعدة التشغيل.
2. أضف الموردين والأعضاء، وسجل المخزون الأولي أو التوريد. تسجل كل حركة في دفتر المخزون والقيود المالية المرتبطة.
3. اضبط اسم الفرع وعنوانه وهاتفه وسياسة الاسترجاع في إعدادات الفاتورة. الشعار محفوظ محليًا. العبارة الافتراضية للاسترجاع تطلب الاحتفاظ بالفاتورة فقط؛ لا تختلق مدة تجارية أو سياسة مؤسسية غير متوفرة.
4. افتح وردية برصيد افتتاحي، ثم امسح الباركود أو اختر الصنف. تحقق من العضو واختر الخصم صراحة. أتم السداد نقدًا أو كي نت أو بتقسيم المبلغ.
5. اعرض الإيصال واطبعه من زر الطباعة. اختر ورق 80mm في إعدادات الطابعة، وأوقف ترويسة وتذييل المتصفح. إدخال تحصيل كي نت يسجل السداد ومرجعه؛ لا يتصل بجهاز دفع بنكي خارجي.
6. للمرتجعات، أدخل رقم الفاتورة، وحدد الكمية والحالة والسبب. السليم يعاد للمخزون، والتالف يسجل منفصلًا. يحسب الخادم الاسترداد من الفاتورة الأصلية.
7. قبل إغلاق الوردية أتم السلة الحالية واسترجع السلات المعلقة وزامن العمليات المؤجلة، ثم أدخل النقد الفعلي. يعرض النظام تقرير Z والفارق.

## العمل دون اتصال

انقطاع الإنترنت وحده لا يؤثر على الخادم المحلي أو SQLite. عند انقطاع الخادم أيضًا، يحتفظ المتصفح بالواجهة والكتالوج والعضوية والخصومات والوردية والسلة عبر Service Worker وIndexedDB. يلزم دخول ناجح وفتح وردية ومزامنة الكتالوج قبل أول استخدام دون الخادم.

تُحفظ المبيعات المؤجلة بـ UUID دائم، وتُخصم الكميات من الرصيد المحلي. يظهر الإيصال بوضوح كعملية مؤجلة إلى أن يمنحها الخادم رقم الفاتورة التسلسلي. تعاد المزامنة تلقائيًا كل 20 ثانية أو من مؤشر الاتصال. لا يحدث خصم ثانٍ عند إعادة UUID نفسه. تُحفظ السلات المعلقة محليًا أيضًا عند الانقطاع.

المخزون المشترك والأسعار والعضوية يعاد التحقق منها في الخادم. إذا تغيرت أو أُغلقت الوردية من جهاز آخر، تبقى العملية المرفوضة محفوظة ويظهر سبب رفضها في نافذة المزامنة لمعالجة بياناتها. لا يمكن ضمان مخزون مشترك لحظي بين أجهزة منفصلة أثناء انقطاع الخادم. فتح وإغلاق الورديات والإدارة والمرتجعات تحتاج الخادم لحماية الدفاتر المركزية.

## المحاسبة الداخلية

دليل حسابات، قيود يومية متوازنة ومحمية من التعديل والحذف، ميزان مراجعة ونتيجة تشغيل، إيرادات ومردودات وتكلفة بضاعة وتلف ومخزون وذمم موردين وسداد. ترحّل عمليات البيع والمرتجع والتوريد والجرد تلقائيًا. تكلفة المخزون متوسط مرجح؛ يُحفظ لكل بند بيع سعر التكلفة الأصلي كي لا تتأثر تكلفة المرتجع بتغير أسعار التوريد.

التوريد أو سداد المورد نقدًا من مستخدم له وردية مفتوحة يسجل خروج النقد من درج ورديته ويظهر في المطابقة. القيود اليدوية متاحة للمدير والمشرف من شاشة القيود اليومية. لا توجد اتصالات أو تبعيات لـ Odoo. هذه وحدة مالية تشغيلية ضمن نطاق المكتبة، وليست ادعاءً بتنفيذ جميع وحدات Odoo غير المحددة في الوثائق.

## البيانات والنسخ الاحتياطية

قاعدة التشغيل: `database/kts_pos.db`. يستخدم SQLite إعدادات WAL والـ PRAGMAs والفهارس المحددة. ينشئ الخادم نسخة متسقة عند تشغيله ثم كل 24 ساعة، ويحتفظ بآخر 30 نسخة في `database/backups`.

للاستعادة: أوقف الخادم، احتفظ بنسخة من قاعدة البيانات الحالية وملفي WAL/SHM إن وجدا، ثم استبدل قاعدة التشغيل بنسخة احتياطية سليمة. لا تستبدل ملف SQLite أثناء تشغيل الخادم. الصور المحلية في `client/images/uploads` تحتاج تضمينًا في النسخ التشغيلية للمجلد؛ نسخ SQLite اليومية تشمل البيانات فقط. يمكن تحديد مكان قاعدة البيانات بالمتغير `KTS_DB_PATH`، والمنفذ بـ `PORT`.

## التحقق

```powershell
npm test
node docs/browser-test.cjs
node docs/performance-test.cjs
```

اختبارات المتصفح تحتاج Playwright/Chromium. تستخدم سكربتات التحقق مسار runtime المتوفر على هذا الجهاز؛ يمكن تحديد `PLAYWRIGHT_MODULE` لمسار Playwright في جهاز آخر. اختبارات الخادم تحتاج تبعيات المشروع فقط. جميعها تنشئ قاعدة بيانات مؤقتة معزولة.

راجع `docs/IMPLEMENTATION_AND_VALIDATION.md` لتفاصيل المطابقة والقرارات ونتائج التحقق، و`docs/DOCUMENT_REVIEW_MANIFEST.json` لبصمات الوثائق وعدد سطورها.
